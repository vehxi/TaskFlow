# Дизайн интерфейса TaskFlow

## 1. Направление

Монохромный минимализм рабочего инструмента: спокойная типографика, тонкие разделители, компактная навигация и понятные действия. Интерфейс использует обычные подписи и линейные иконки. Стилизация под код, терминальные префиксы и декоративные ASCII-элементы не используются. Цветной акцент выбирается отдельно; текущий вариант полностью чёрно-белый.

## 2. Темы и палитра

Темы «Светлая», «Тёмная» и «Как в системе» переключаются в заголовке рабочего пространства и на странице входа. По умолчанию действует системная тема, при её изменении интерфейс обновляется. Явный выбор сохраняется в localStorage под ключом taskflow.theme; при недоступном хранилище работает в пределах текущей страницы. Начальная тема применяется до отображения React.

Статусы и ошибки различаются текстом и обозначениями, а не цветом. Основная кнопка выделяется противоположным контрастом относительно страницы.

## 3. Типографика

Используется Segoe UI (Microsoft), затем Helvetica Neue / Arial и системный sans-serif с поддержкой кириллицы. Моноширинный шрифт не применяется. Заголовок рабочего экрана — 28–36 px / 600, line-height 1.1, letter-spacing −0.022em; основной текст — 13–14 px, подписи — 11–12 px. Числа используют tabular-nums. Большой рекламный заголовок отсутствует в рабочих разделах.

## 4. Компоненты

Шкала скруглений: small 4 px, control 8 px, panel 12 px. Кнопки имеют постоянный радиус 8 px; основные действия — высоту от 46 px. На нажатие применяется scale(0.95) за 120 ms; reduced-motion отключает масштабирование. Hover применяется только для указателя с поддержкой наведения. Фокус виден через обводку 3 px. У полей есть постоянные подписи и связанные сообщения ошибок; пароли повторно не показываются.

## 5. Компоновка

На широком экране боковая навигация занимает 236 px, отступ рабочего поля — 48 px. Заголовок, пояснение и главное действие образуют начало страницы; затем следует список с разделителями и пагинация. Имена, email, роли и доступ читаются независимо. Формы разделены на данные, роли и активность. Рабочие экраны не заполняются декоративными карточками.

## 6. Поверхности

Иерархия строится на ступенях серого: навигация, рабочее поле, поля ввода и выбранные элементы. Тени сдержанные; размытие и градиенты отсутствуют. В тёмной теме используется мягкий светлый текст, без чистого белого на всём экране.

## 7. Ограничения

Компоненты оформляются через CSS Modules, глобальный файл содержит сброс и общие токены. Новые зависимости для оформления не требуются. Текст пользователей экранируется React. Ссылки меняют маршрут, кнопки выполняют действие; проверка прав остаётся на сервере. Цвет темы не влияет на доступные операции. Пустые состояния показывают отсутствие данных, без вымышленных записей.

## 8. Адаптивность

До 760 px боковая навигация становится верхней; данные пользователя складываются в компактные строки, формы — в одну колонку. Минимальная интерактивная область — 40 px. Длинные имена и email переносятся. Приёмка оформления включает широкий экран, 375 px, обе темы и навигацию с клавиатуры.

## 9. Продолжение оформления

Новые экраны используют семантические токены вместо жёстко заданных цветов:

- Основное действие: accent / on-accent, шрифт 13 px / 600, радиус 8 px, высота от 46 px, нажатие scale(0.95) / 120 ms.
- Заголовок: ink, 28–36 px / 600, line-height 1.1, letter-spacing −0.022em.
- Поле: paper / ink, радиус 8 px, высота от 48 px, разделитель line и постоянная подпись.

Пробный вариант предназначен для согласования общей композиции и двух тем; выбор цветного акцента выполняется отдельно.
