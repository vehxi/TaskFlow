# Экраны и действия пользователей

Проект экранов для [архитектуры](architecture.md), [матрицы прав](explanatory-note.md) и [сценариев](use-cases.md).

## Навигация и общие правила

После входа пользователь видит доступные разделы своих ролей: «Пользователи» и «Справочники» для администратора, «Мои проекты» для руководителя, «Мои задачи» для исполнителя. При совмещении разделы объединяются; отдельное переключение роли не меняет серверных прав. Начальная страница выбирает первый доступный раздел в этом порядке, сохраняя ссылки на остальные.

Экраны реализуются в React + TypeScript, сборка и локальный сервер — Vite. В рабочем пространстве отображаются имя текущего пользователя и выход. Списки с пустым результатом объясняют, что записей нет. Поля имеют подписи; ошибки появляются рядом с полями или в сообщении формы. React отправляет команду через API, обновляет состояние и переходит к сохранённой карточке. Обновление страницы повторяет только чтение; кнопка сохранения недоступна до завершения запроса. Пароль при ошибке формы не заполняется повторно.

Маршруты таблицы принадлежат клиентскому роутеру React; перечень описывает целевой интерфейс, а не завершённость реализации всех экранов. Данные загружаются через [API](api-contract.md), изменения отправляются JSON-командами с CSRF. Вход и выход используют отдельный контракт сессии. Открытие URL или обновление страницы не изменяет данные.

## Карточка задачи

Формы изменения, комментария и времени содержат ожидаемую версию задачи. После сохранения новая версия используется всеми формами карточки. При конфликте пользователь видит предложение обновить данные; автоматическая повторная отправка не выполняется. При закрытии редактирование, комментарии и время недоступны. Выполненная или отменённая задача остаётся доступной для чтения по общим правилам.

Для исполнителя переходы — начало и завершение; отмена и повторное открытие доступны руководителю. Руководитель без назначения себе и дополнительной роли исполнителя не получает форму учёта времени. Кнопки показываются по разрешениям, но сервер повторно проверяет каждое действие. Поля авторов, статуса при обычном редактировании и проекта существующей задачи не позволяют произвольную подмену.

При смене назначения прежние комментарии и минуты видны новому исполнителю с исходным авторством. После сохранения с ошибкой SMTP сообщение прямо говорит: «Данные сохранены. Уведомление не отправлено»; форма создания повторно не отправляется. При отсутствии уведомляемого события отдельного сообщения о почте нет.

## Адаптивность и доступность

Контрольные ширины — 375 и 1440 CSS-пикселей. На узком экране формы перестраиваются в одну колонку, навигация остаётся доступной, широкие отчётные таблицы прокручиваются в собственном контейнере. Числа и заголовки не обрезаются без способа прочитать полное значение. Цвет не является единственным обозначением статуса или ошибки.

Проверяются порядок фокуса, клавиатурные действия и связь label с полем. Пользовательский текст выводится как текст в JSX с экранированием React; dangerouslySetInnerHTML не используется; комментарии не обрабатываются как произвольный HTML. Имена, описания и ошибки не раскрывают недоступные объекты.
