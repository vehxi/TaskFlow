# Запуск приложения

Перед запуском выполните [подготовку окружения](SETUP.md): настройте PostgreSQL и файл `.env`. Все команды выполняются из корня проекта.

## Запуск сервера через Gradle

**macOS / Linux:**

```bash
./gradlew bootRun
```

**Windows (PowerShell):**

```powershell
.\gradlew.bat bootRun
```

Flyway создаст таблицы и назначит права подключения приложения. При следующих запусках он проверит применённые миграции и выполнит новые.

После сообщения `Started TaskFlowApplication` Spring API работает на `http://localhost:8080`. Затем запустите интерфейс в отдельном терминале. Учётные записи PostgreSQL используются только сервером для подключения к БД.

Сервер работает, пока команда `bootRun` выполняется. Остановка — `Ctrl+C`.

Для проверки созданных системных ролей выполните команду в терминале macOS, Linux или Windows PowerShell:

```shell
psql -h localhost -U task_tracker_app -d task_tracker -W -c "SELECT code FROM roles ORDER BY code;"
```

Ожидаются три значения: `ADMIN`, `EXECUTOR`, `MANAGER`.

## Запуск интерфейса

Сервер Spring должен оставаться запущенным. Во втором терминале из корня репозитория выполните команды, одинаковые для macOS, Linux и Windows PowerShell:

```shell
npm --prefix frontend install
npm --prefix frontend run dev
```

После появления локального адреса откройте [http://localhost:5173](http://localhost:5173). Vite использует порт 5173 и проксирует `/api` на `http://127.0.0.1:8080`; при занятом порте он сообщает об ошибке. Используйте один адрес браузера — `localhost:5173`; переход на другой hostname создаёт отдельную область cookie.

В форме входа укажите email и пароль пользователя приложения. Для первого входа выполните [создание администратора](SETUP.md#4-создание-начального-администратора). Администратор попадает в «Пользователи»; другие роли пока видят свою учётную запись. Выход завершает серверную сессию. Остановка Vite — `Ctrl+C` во втором терминале.

Если изменён `SERVER_PORT`, укажите соответствующий адрес backend в `frontend/vite.config.ts`. Если нужны ссылки из писем на локальный интерфейс, задайте `APP_BASE_URL=http://localhost:5173` в серверном `.env`. Не копируйте пароли БД в `frontend/`: переменные Vite с префиксом `VITE_` попадают в браузерную сборку.

После первой успешной установки сохраните сформированный `frontend/package-lock.json` в репозитории. Для последующих установок по lockfile используйте `npm --prefix frontend ci`.

## Запуск из IntelliJ IDEA

1. Откройте `build.gradle` как Gradle-проект.
2. Выберите JDK 21 для проекта и Gradle JVM.
3. Дождитесь импорта зависимостей.
4. Запустите `TaskFlowApplication` или Gradle-задачу `bootRun`.
5. В отдельном терминале запустите интерфейс командами из раздела выше.

Рабочий каталог конфигурации запуска — корень проекта, где находится `.env`.

## Запуск JAR

Сначала выполните [сборку интерфейса и исполняемого JAR](TESTING.md#сборка-исполняемого-jar). React включается в JAR как статические файлы; Node.js на машине запуска готового JAR не требуется.

Выполните команду из корня проекта с JDK 21:

**macOS / Linux:**

```bash
java -jar build/libs/taskflow-0.1.0.jar
```

**Windows (PowerShell):**

```powershell
java -jar .\build\libs\taskflow-0.1.0.jar
```

После запуска JAR откройте [http://localhost:8080](http://localhost:8080). Отдельный Vite в этом режиме не запускается. Для ссылок в письмах используйте `APP_BASE_URL=http://localhost:8080`.

Проверки и артефакты описаны в [инструкции тестирования и сборки](TESTING.md).
